=== 1. SERVICE BACKEND (FastAPI) ===

1. Créez un service "GitHub Repo" : duareg/appsmith-seka
2. Allez dans Settings > Root Directory : /backend
3. Allez dans Variables > RAW Editor (en haut à droite)
4. Collez tout ceci :

PROJECT_NAME=SEKA Production
ENVIRONMENT=production
DEBUG=false
SECRET_KEY=YOUR_SECRET_KEY_HERE
ACCESS_TOKEN_EXPIRE_MINUTES=60
REFRESH_TOKEN_EXPIRE_MINUTES=10080
TOKEN_ALGORITHM=HS256
DATABASE_URL=${{Postgres.DATABASE_URL}}
BACKEND_CORS_ORIGINS=["https://app.sekagestion.com","https://sekagestion.com","https://www.sekagestion.com","http://localhost:3000"]
DOMAIN=sekagestion.com
FRONTEND_URL=https://app.sekagestion.com
MINDEE_API_KEY=md_YOUR_MINDEE_KEY_HERE
STRIPE_API_KEY=pk_test_YOUR_STRIPE_PUBLIC_KEY_HERE
STRIPE_SECRET_KEY=sk_test_YOUR_STRIPE_SECRET_KEY_HERE
KKIAPAY_PUBLIC_KEY=YOUR_KKIAPAY_PUBLIC_KEY
KKIAPAY_PRIVATE_KEY=YOUR_KKIAPAY_PRIVATE_KEY
KKIAPAY_SECRET=YOUR_KKIAPAY_SECRET
RESEND_API_KEY=re_YOUR_RESEND_KEY_HERE
RESEND_FROM_EMAIL=noreply@sekagestion.com
RESEND_FROM_NAME=SEKA

5. Allez dans Settings > Deploy > Deploy Command :
python3 run_migrations_safe.py && uvicorn app.main:app --host 0.0.0.0 --port $PORT

=== 2. SERVICE FRONTEND (Next.js) ===

1. Créez un service "GitHub Repo" : duareg/appsmith-seka
2. Allez dans Settings > Root Directory : /frontend
3. Allez dans Variables > RAW Editor
4. Collez ceci (remplacez l'URL par celle de votre backend une fois déployé) :

NODE_ENV=production
NEXT_PUBLIC_API_BASE_URL=https://api.sekagestion.com


=== 3. DOMAINES ===

1. Service Backend > Settings > Networking > Custom Domain : api.sekagestion.com
2. Service Frontend > Settings > Networking > Custom Domain :
   - app.sekagestion.com (primary)
   - www.sekagestion.com (if using this domain for frontend)

   IMPORTANT: Ensure ALL frontend domains are included in BACKEND_CORS_ORIGINS above!

=== 4. POSTGRESQL ===

Créez simplement un service "Database" > "PostgreSQL". C'est tout !
Le backend se connectera automatiquement grâce à ${{Postgres.DATABASE_URL}}

=== 5. DÉPANNAGE DATABASE MIGRATIONS ===

Si vous voyez des erreurs "relation already exists" dans les logs :

1. Le problème : Multiple replicas essaient de créer les tables en même temps
2. La solution : Utiliser `run_migrations_safe.py` (déjà configuré ci-dessus)
3. Ce script utilise des PostgreSQL advisory locks pour éviter les race conditions
4. Si les migrations échouent encore, vous pouvez les réinitialiser :
   ```bash
   # Se connecter à la base de données Railway
   # Supprimer la table alembic_version si nécessaire
   # Puis redéployer
   ```

=== 6. DÉPANNAGE CORS ===

Si vous rencontrez des erreurs CORS, vérifiez :

1. **Vérifier les variables d'environnement Railway** :
   - Assurez-vous que ENVIRONMENT=production
   - Vérifiez que BACKEND_CORS_ORIGINS contient tous les domaines frontend
   - Format: ["https://www.sekagestion.com","https://app.sekagestion.com"]

2. **Vérifier les logs Railway** :
   - Cherchez "🌐 CORS Configuration" dans les logs au démarrage
   - Vérifiez que les origines configurées sont correctes

3. **Tester avec le script** :
   ```bash
   cd backend
   ./test_cors.sh
   ```

4. **Cloudflare (si utilisé)** :
   - Vérifiez que le WAF ne bloque pas les requêtes
   - Désactivez temporairement "Browser Integrity Check" dans Security > Settings
   - Vérifiez les règles de pare-feu (Firewall Rules)

5. **Vérifier l'endpoint de santé** :
   ```bash
   curl https://api.sekagestion.com/
   ```
   Devrait retourner la configuration CORS actuelle
